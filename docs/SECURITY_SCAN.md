## Commands

Run from the repository root with the project venv active.

```sh
python -m pip install -q bandit pip-audit detect-secrets

# SAST on shipped code (tests excluded: pytest asserts are B101 by design)
python -m bandit -r airlock redteam demo -q
python -m bandit -r airlock redteam demo -q --ignore-nosec   # audit the suppressions too

# Declared runtime dependencies (the "proxy" extra), pinned to the installed versions
printf 'fastapi==0.160.0\nhttpx==0.28.1\nuvicorn==0.54.0\n' > /tmp/requirements-runtime.txt
python -m pip_audit -r /tmp/requirements-runtime.txt --progress-spinner off
python -m pip_audit --progress-spinner off                    # whole venv, informational

# Secrets in the working tree
detect-secrets scan --all-files \
  --exclude-files '(^|/)(\.venv|\.git|__pycache__|\.pytest_cache|\.ruff_cache)(/|$)' .
```

The core package has no runtime dependencies (`dependencies = []`); only the
optional `proxy` extra pulls fastapi, httpx and uvicorn. pip-audit resolved
those three plus their transitive dependencies (starlette, pydantic, anyio, h11
and so on).

## What was fixed

1. **Fail-open paths now fail closed** (`engine.py`, `segments.py`, `tools.py`,
   `sanitize.py`). The four B112 blocks skipped what they could not read and the
   skipped text was still forwarded to the model. Concretely:
   - a malformed message hid itself from every detector;
   - an MCP tool whose checks raised was never checked;
   - a description nested deeper than 64 levels in an `input_schema` was never
     scanned, yet the model still received it (a detection bypass that any
     malicious MCP server could use);
   - a body too deeply nested for `copy.deepcopy` made `sanitize()` return the
     original body, and the proxy then forwarded the unredacted bytes.

   Each of these now reports `(path, reason)` to the engine, which adds one
   `AIR-FAIL-CLOSED` finding (CRITICAL, LLM01) and returns BLOCK. The evidence
   names paths only, never content. The extractor still never raises, other
   findings are still reported, and the four `# nosec B112` comments are gone
   because the pattern is gone. Covered by `tests/test_fail_closed.py`.
2. **Proxy no longer blocks its event loop** (`proxy.py`, OWASP LLM10 unbounded
   consumption). `Airlock.inspect()` used to run synchronously inside the async
   handler, so the first scan of a large tool result (about 1 to 2 s per MB)
   froze every other request, health checks and streams included. It now runs
   in a worker thread through `run_in_threadpool`; a lock keeps one inspection at
   a time so tool pinning stays ordered as before.
3. **Deeply nested JSON** sent to `/v1/messages` raised an uncaught
   `RecursionError` in `json.loads`. It is now a clean 400, like any invalid JSON.
4. **Secret-shaped test literals** in `tests/test_secrets.py` and
   `tests/test_hidden.py` are now built from parts at runtime, so repository
   scanners (detect-secrets, gitleaks, GitHub push protection, Snyk) do not flag
   them. The detector tests run on the same strings as before.
5. **Dev environment**: the venv's pip was upgraded from 25.1.1 to 26.2.2.
6. **Horizon client** (`attest.py`, bandit B310): `_get_json` now refuses any
   URL that does not start with `https://` (the Horizon base is a parameter, so
   `file://` was reachable), and reads at most 2 MB of the response instead of
   an unbounded `resp.read()`.

No other suppression is in place. Tests are excluded from bandit only because
pytest relies on `assert` (421 x B101, all in `tests/`).

## Verified and unchanged

- `airlock serve` and the demo mock upstream bind `127.0.0.1` by default.
- Request bodies are capped at 10 MB, both from Content-Length and while streaming.
- Upstream calls use explicit httpx timeouts (connect 10 s, pool 10 s, read and
  write 600 s for long generations).
- An exception inside inspection returns HTTP 500 and nothing is forwarded.
- The audit log is created with mode 0600, is hash-chained with SHA-256, and holds
  rule ids, paths and hashes, never prompt text, evidence or API keys. API keys
  are forwarded to the upstream but never logged.
- No `eval`, `exec`, `subprocess`, `pickle`, `yaml.load`, `shell=True`, MD5 or
  SHA-1 in `airlock/`, `demo/` or `scripts/`. Trace ids come from `secrets`.
- CI runs with `permissions: contents: read` and `persist-credentials: false`.

## Open items

- `airlock/attest.py` still interpolates `tx_hash` and `address` into Horizon
  URLs without validating their format. The host is fixed, so the impact is
  limited to other paths on the same Horizon server; validating them (64 hex
  characters, `G` plus 55 base32 characters) or passing them through
  `urllib.parse.quote(value, safe="")` would close it.
- ruff reported long lines (E501) in `demo/demo.py`, which teammates were editing
  during the scan. Style only, not a security issue.
- Re-run detect-secrets after the last change to `docs/testnet/`: those files are
  regenerated by `scripts/testnet_attest.py`.

## Snyk (official scan)

The Snyk CLI is reachable through npm (`npx --yes snyk --version` printed
1.1308.2), but it needs an account token and this scan did not authenticate.
Run it with your own account:

```sh
npx snyk auth
npx snyk test --file=pyproject.toml --package-manager=pip
npx snyk code test
```

Because `pyproject.toml` declares no mandatory dependencies, also scan the
resolved environment, the same way CI does:

```sh
python -m pip freeze --exclude-editable > requirements-snyk.txt
npx snyk test --file=requirements-snyk.txt --package-manager=pip
```

In CI, add the `SNYK_TOKEN` repository secret: the Snyk open source and Snyk
Code steps in `.github/workflows/ci.yml` then become hard gates instead of
informational steps.
